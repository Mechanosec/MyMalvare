# Fishing Analizer Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Зробити код читабельним і типізованим зі збереженням поведінки прототипу.

**Architecture:** Спільні контракти й налаштування, стандартні TypeScript imports, окремі панель розширення та HTTP-обробник. Контролер координує аналіз листа; адаптери працюють з провайдерами. Нові фреймворки та runtime-залежності не потрібні.

**Tech Stack:** TypeScript, esbuild, Node HTTP, Chrome Manifest V3, node:test, jsdom.

**Spec:** `fishingAnalizer/docs/superpowers/specs/2026-09-23-refactor-design.md`

## Global Constraints

- Зберегти каталоги `backend`, `extection`, `localModel`, npm-команди та `dist/extection`.
- Зберегти HTTP API, CORS, дозволені поля, ліміти, моделі, endpoints, таймаути, заборону redirects і правила вердиктів.
- Не змінювати формат Chrome storage та ключа згоди `${serverUrl}|${mode}`.
- Не записувати й не логувати вміст листів; не вставляти їхній HTML.
- Не змінювати очікування 19 наявних поведінкових тестів.
- Не додавати popup, редизайн, нові можливості чи runtime-залежності.
- Не перевстановлювати Laya; не виконувати платних API-викликів.
- Не виконувати commit, push або deploy.

Усі команди виконуються з `fishingAnalizer/`. Фінальні перевірки мають одного власника; паралельно збірки не запускаються.

## Review Focus

1. Відповідь після відкликання згоди чи зміни сервера: старий вердикт не показується.
2. Некоректний JSON або network error: помилка без вердикту, повторна спроба можлива.
3. Зміни DOM від панелі: однаковий лист не надсилається повторно.
4. Зібраний Chrome script: запускається самостійно, без `FishingDom`/`FishingController`.
5. Недовірений HTTP-запит: CORS, валідація та проєкція полів залишаються чинними.

## Task 1: Спільні контракти та стандартні модулі

**Owner:** Parent.

**Files:** Перенести `types.ts` у `shared/contracts.ts`; створити `shared/settings.ts`, `test/settings.test.ts`; змінити `scripts/build.ts`, `tsconfig.json`, `extection/manifest.json`; механічно змінити imports/exports у production-модулях і тестах.

**Interfaces:**

```ts
// shared/contracts.ts
export type Mode = 'jev' | 'local';
export type Status = 'suspicious' | 'review' | 'no_signals';
// MailMessage, Observation, AnalyzeResult зберігають наявні поля.
export type AnalyzeRequest = { requestId: string; mode: Mode; message: MailMessage };
export type AnalysisFailure = { requestId?: string; error: { code: string; message: string } };
export function isMode(value: unknown): value is Mode;
export function isStatus(value: unknown): value is Status;
export function isMailMessage(value: unknown): value is MailMessage;

// shared/settings.ts
export type Settings = { serverUrl: string; mode: Mode };
export const DEFAULT_SETTINGS: Settings;
export function serverEndpoint(value: string): string | null;
export function consentKey(settings: Settings): string;
```

- [ ] Запустити `npm test` як базову перевірку.
- [ ] Додати `test/settings.test.ts` з адресами `http://127.0.0.1:8787`, `http://localhost:8787/`, відхиленням `127.0.0.1.evil.test`, шляху та userinfo; перевірити, що ключ залишається `http://localhost:8787|local`.
- [ ] Додати settings-test entrypoint до збірки й запустити `npm run build`; очікувана помилка відсутнього модуля.
- [ ] Перенести типи й чинний `validMessage` (як `isMailMessage(unknown)`) без зміни лімітів. Перенести `serverEndpoint` без зміни нормалізації.
- [ ] Замінити `require`/`module.exports` та UMD на imports/exports. `content.ts` імпортує контролер, контролер імпортує DOM. Імпорт тестованих функцій у Node не має вимагати Chrome globals.
- [ ] Build script збирає browser IIFE для `content`, `background`, `options`, CommonJS для backend і тестові bundles експортованих модулів. Manifest завантажує `content.js` одним файлом.
- [ ] Додати `shared`, `scripts`, `test` до TypeScript-перевірки; типізувати тестові doubles вузькими API-типами.
- [ ] Запустити `npm run build`, потім `node --test test/*.test.ts`; наявні сценарії та settings-перевірки мають пройти.

**Handoff:** Спільні сигнатури зафіксовані. Backend і extension можна змінювати незалежно; parent погоджує зміни контрактів.

## Task 2: Відокремити HTTP від аналізу

**Owner:** Backend implementer.

**Files:** Створити `backend/http.ts`, `backend/home-page.ts`; змінити `backend/index.ts`, `backend/analyze.ts`, `backend/adapters.ts`, `test/server.test.ts`. Parent додає HTTP entrypoint до build script перед focused check.

**Interfaces:**

```ts
// backend/http.ts
export type HandlerOptions = { fetcher?: typeof fetch; env?: NodeJS.ProcessEnv };
export function createHandler(options?: HandlerOptions):
  (request: IncomingMessage, response: ServerResponse) => Promise<void>;
// backend/home-page.ts
export const homePage: string;
// backend/analyze.ts
export async function analyze(mode: Mode, message: MailMessage,
  options: HandlerOptions): Promise<Omit<AnalyzeResult, 'requestId' | 'mode'>>;
```

- [ ] Перевести імпорт server tests на `dist/backend/http.js`; `node --test test/server.test.ts` спочатку має виявити відсутній модуль.
- [ ] Перенести `createHandler` у `http.ts`, незмінний HTML у `home-page.ts`. В `index.ts` залишити лише `createServer(createHandler()).listen(...)`.
- [ ] Виділити читання JSON, JSON-відповідь та проєкцію дозволених полів. Зовнішній JSON починається з `unknown`; catch не повертає текст upstream exception.
- [ ] Назвати кроки аналізу `collectObservations`, `resolveStatus`, `buildLimitations`; виділити конфігурацію двох провайдерів у `adapters.ts` без registry.
- [ ] Додати CORS-тест: `Origin: https://evil.example` для `/health` дає 403. Некоректний JSON `body: '{'` для `/analyze` дає 400 без поля `status`. Зберегти тест проєкції полів і перевірки endpoints.
- [ ] Запустити `npm run build`, потім `node --test test/server.test.ts`; жодного реального виклику моделі.
