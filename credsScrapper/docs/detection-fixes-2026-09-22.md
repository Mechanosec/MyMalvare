# Перша ітерація виправлень детекції

Робоча гілка: `codex/credential-detection-fixes` в ізольованій робочій копії.
Два агенти реалізували незалежні зміни, третій виконав рев’ю; інтеграцію
й загальні перевірки виконав координатор. Комітів і push немає.

## Реалізовано

- Facebook/Twitter: відхилення збігів усередині довших токенів/base64 та
  перед base64-padding; Twitter більше не обрізається до 65 символів.
  Початкові `+`/`-` справжнього unified diff не блокують детекцію.
- GCP: маркер service_account і PEM-заглушки більше не утворюють GCP
  знахідку. Потрібні поля service-account JSON та локально читабельний
  RSA private key від 2048 біт. Мережевої перевірки під час детекції немає.
  Назви project_id/email зі словами test/example залишаються допустимими.
- AWS: однозначні credentials з одного env-блока або плоского JSON
  зберігаються як одна знахідка типу aws_access_key_id зі значенням
  `{"access":"...","private":"..."}`. За наявності зберігається sessionToken.
  Підтримуються завершені JSON та env-блоки одного боку diff.
  Фільтр лише aws_access_key_id також збирає private-частину.
- Неповні/неоднозначні AWS знахідки залишаються окремими. Немає підбору
  першого secret із репозиторію ані для одиничної, ані для масової перевірки.
  Валідатор читає JSON-пару; live-перевірка ASIA залишається unsupported.
- Виправлено перекриття специфічних та entropy-збігів і збереження номерів
  рядків під час пропуску багаторядкового MIME base64.

## Перевірки

- Регресії відтворено тестами перед виправленнями.
- TypeScript: `tsc --noEmit -p apps/api/tsconfig.json`.
- Збірка: `npm run build -w apps/api`.
- Повний API-набір: **60 suites / 463 тести пройшли**. Команда: `npm run test -w apps/api -- --runInBand`.
  Для Git-fixtures лише в середовищі процесу вимкнено інтерактивний підпис
  тимчасових комітів через GIT_CONFIG_COUNT/commit.gpgsign=false.
- Worker-інтеграції використовують попередньо зібраний dist; Redis-тести
  виконано на окремому тимчасовому контейнері без volume/persistence.
  Попередні повні запуски до підготовки цього оточення перервано.
- Справжня тимчасова SQLite перевіряє шлях scanText → збереження однієї
  JSON-пари → читання валідатором. Provider fetch у тестах замінено mock.
- Окреме рев’ю виявило й перевірило виправлення квадратичного обходу AWS
  та видалення однойменного токена із сусіднього об’єкта в одному рядку.
  Фінальний синтетичний benchmark: 2/4/8 тис. JSON-пар — 31/46/86 мс;
  кількість вихідних пар відповідає вхідній. Це локальний вимір, не SLA.
- Перевірки hex-architecture, secret-handling і simplicity: відкритих
  зауважень у фінальному diff немає. Web не змінено, його тести не запускалися.

## Дані та межі

Робочі бази не змінювалися. `detection-cleanup-dry-run.json` містить тільки
ID й причини для 5 структурно неповних GCP-записів; це попередній перегляд,
не автоматичне очищення всіх старих знахідок. Реальні ключі не надсилалися
провайдерам. Старі одиночні AWS ID потребують повторного пасивного сканування
джерел — із самої бази відсутню private-частину відновити неможливо.

`.example` не внесено в загальний blacklist: реальний ключ у шаблоні також
є витоком. Відсіюються підтверджені помилки формату й заглушки, а не кожен
файл із такою назвою. Загальне звуження generic_high_entropy та повний аудит
JWT/Twilio/PEM залишаються наступною ітерацією, як погоджено.

AWS parser навмисно консервативний: пропускає неоднозначні повтори,
незавершений JSON, змішані сторони/hunks і JSON-кандидати понад 8192 символи.
Такі половинки зберігаються окремо. Зміна детектора сама по собі не видаляє
історичні хибні знахідки з бази.
