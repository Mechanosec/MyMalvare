# Друга ітерація: generic-знахідки в медіаданих

У базі `apps/api/prisma/dev.db` є 3 217 002 generic_high_entropy
знахідки, з них 1 454 863 у `.ipynb`. Розширення файлу й відсутність
контексту не доводять, що кожен запис хибний. Базу не змінено.

`scanText` тепер замінює base64-значення лише в явних JSON-полях
`image/png`, `image/jpeg`, `image/gif`, `image/webp` та `application/pdf`.
Підтримано значення одним рядком та масив фрагментів у unified diff.
Довжина тексту й номери рядків зберігаються. Значення інших полів,
зокрема credential-присвоєння поруч, скануються як раніше.

Синтетичні регресії спершу виявляли зайві generic-знахідки, після зміни
пройшли: медіа-фрагменти відсікаються, сусідній ключ залишається.
Перевірено `tsc --noEmit -p apps/api/tsconfig.json`,
`npm run build -w apps/api`, повний `npm run test -w apps/api -- --runInBand`:
61 suite, 465 тестів пройшли. Redis-тести виконані з окремим тимчасовим
контейнером; його прибрано. Застосовано reviews архітектури, роботи з
секретами й простоти, нових порушень у цьому вузькому diff немає.

Це не класифікує історичні записи: у SQLite є лише знайдений токен і шлях,
а не вся структура JSON-поля, тому неможливо чесно порахувати, скільки
старих знахідок належало медіаданим. Для виправлених правил потрібен
повторний пасивний скан; автоматичного видалення старих рядків немає.

Наступні окремі проходи: generic-значення з інших структурованих blob,
JWT, підозрілі Twilio-формати й PEM-блоки. Жоден тип не слід видаляти
лише через його масову частоту в базі.
