# Третя ітерація: SRI та історичний generic

Для нових сканувань `generic_high_entropy` пропускає повні публічні
Subresource Integrity checksum лише всередині явного HTML/JSON `integrity`:
`sha256`, `sha384` або `sha512` з коректною довжиною та base64. Самостійний
високоентропійний токен, сусідній токен та збіги специфічних детекторів
залишаються видимими. Правило не міняє глобальний entropy threshold.

Під час незалежного рев’ю виправлено два GCP краї: відхилений
service-account JSON більше не приглушує generic-знахідку в сусідньому
полі, а diff parser не складає credential із доданих і видалених рядків
або різних hunks. Незмінені контекстні рядки можуть належати до обох
сторін diff і залишаються підтриманими.

Історичний зріз `apps/api/prisma/dev.db` до очищення містив 3 232 919
знахідок, з них 3 217 002 `generic_high_entropy`. За окремим дозволом
власника видалено тільки 212 generic-записів із dependency lockfiles.
Зроблено локальну SQLite резервну копію й перевірено цілісність до й
після транзакції. Деталі та ID наведено в
[`detection-history-cleanup-2026-09-22.md`](detection-history-cleanup-2026-09-22.md)
та [`generic-history-preview-2026-09-22.json`](generic-history-preview-2026-09-22.json).

Решту історичних generic-знахідок не перекласифіковано: таблиця зберігає
знайдений токен і короткий контекст, але не весь HTML/JSON чи notebook
output навколо нього. Через це точний SRI/media-фільтр неможливо
безпечно застосувати до старих рядків лише за полями БД. Нові правила
працюватимуть під час наступного пасивного сканування.

Синтетичні регресії для SRI й GCP спершу відтворили помилки, потім
пройшли. Фінальна перевірка: detection unit suite — 212/212, повний
API Jest — 479/479 (61 suites), `tsc --noEmit` і API build — без помилок.
Тимчасовий Redis для тестів зупинено; production БД тестами не змінювалась.
Обов’язкові перевірки архітектури, обробки секретів і простоти нових
зауважень після виправлень не виявили.
